# ربات تلگرامی فروش کانفیگ V2Ray (Railway + Docker)

ربات Python/aiogram با قابلیت‌های زیر:
- نمایش پلن‌ها و قیمت‌ها
- کیف پول داخلی با ثبت درخواست شارژ و تأیید مدیر
- خرید از موجودی کیف پول
- تحویل خودکار کانفیگ از موجودی آماده (مدیر کانفیگ‌ها را دستی وارد می‌کند)
- ثبت سفارش و نمایش سفارش‌های قبلی
- مدیریت پلن‌ها، موجودی، شارژ و آمار از داخل تلگرام
- SQLite روی Railway Volume

## 1) ساخت ربات با BotFather
1. در تلگرام، حساب رسمی `@BotFather` را باز کنید.
2. دستور `/newbot` را بفرستید.
3. نام نمایشی و username ربات را وارد کنید؛ username باید به `bot` ختم شود.
4. توکن را کپی کنید و محرمانه نگه دارید. توکن را در کد یا مخزن عمومی قرار ندهید.
5. برای پیدا کردن شناسه عددی تلگرام مدیر، به یک ربات معتبر نمایش User ID پیام دهید یا از یک روش قابل‌اعتماد دیگر استفاده کنید. شناسه باید عددی باشد، نه username.

## 2) انتشار کد در GitHub
1. ZIP را استخراج کنید.
2. یک repository بسازید و فایل‌های پروژه را در ریشه آن قرار دهید.
3. فایل `.env.example` فقط نمونه است؛ توکن واقعی را در آن وارد نکنید.
4. repository را به Railway متصل کنید.

## 3) دیپلوی روی Railway
1. در Railway یک Project بسازید و از GitHub یک سرویس Deploy کنید.
2. Railway به‌طور خودکار `Dockerfile` را پیدا می‌کند.
3. در بخش Variables این متغیرها را تنظیم کنید:
   - `BOT_TOKEN`: توکن BotFather
   - `ADMIN_IDS`: شناسه عددی مدیر؛ برای چند مدیر با کاما جدا کنید، مثل `11111111,22222222`
   - `DB_PATH`: مقدار `/data/store.db`
   - `CURRENCY`: `تومان` (اختیاری)
4. در بخش Volumes یک Volume بسازید و آن را به مسیر `/data` متصل کنید. بدون Volume، SQLite ممکن است با redeploy/restart از دست برود.
5. لاگ Deploy را بررسی کنید؛ پیام `Bot polling started` باید دیده شود.
6. ربات را در تلگرام باز کنید و `/start` بزنید.

## 4) دستورات مدیریت
این دستورات فقط برای شناسه‌هایی که در `ADMIN_IDS` هستند کار می‌کنند.

- `/admin` — راهنمای دستورات
- `/addplan نام|قیمت|حجمGB|روز` — افزودن پلن؛ مثال: `/addplan تست|100000|20|30`
- `/plansadmin` — نمایش پلن‌ها
- `/toggleplan ID` — فعال/غیرفعال کردن پلن
- `/addconfig PLAN_ID` — سپس لینک کانفیگ را در پیام بعدی ارسال کنید
- `/cancel` — لغو انتظار دریافت کانفیگ
- `/inventory` — موجودی آماده و فروخته‌شده
- `/credit USER_ID AMOUNT` — شارژ دستی کیف پول
- `/debit USER_ID AMOUNT` — کسر اعتبار
- `/topups` — فهرست درخواست‌های شارژ
- `/stats` — آمار کاربران و فروش

### تحویل خودکار چگونه کار می‌کند؟
مدیر از `/addconfig PLAN_ID` استفاده می‌کند و لینک کانفیگ همان پلن را می‌فرستد. وقتی کاربر پلن را بخرد، ربات در یک تراکنش دیتابیس موجودی را کم می‌کند، سفارش را ثبت می‌کند و کانفیگ را به کاربر می‌فرستد. بنابراین کانفیگ باید از قبل ساخته شده و معتبر باشد؛ این نسخه خودش به Marzban یا Xray متصل نیست.

## 5) شارژ کیف پول
کاربر دکمه «درخواست شارژ» را می‌زند و قالبی مانند `/topup 200000 رسید-تراکنش` می‌فرستد. مدیر درخواست را از پیام دریافتی تأیید یا رد می‌کند. تأیید فقط موجودی داخلی را افزایش می‌دهد و **به‌خودی‌خود پرداخت واقعی را اثبات نمی‌کند**؛ مدیر باید خارج از ربات وجه را بررسی کند. همچنین مدیر می‌تواند با `/credit USER_ID AMOUNT` اعتبار را مستقیماً اضافه کند.

## نکات مهم پیش از استفاده واقعی
- درگاه پرداخت واقعی در این نسخه وجود ندارد.
- از کانفیگ‌هایی استفاده کنید که مالک یا مجاز به فروش آن‌ها هستید.
- توکن BotFather و شناسه‌های مدیریتی را محرمانه نگه دارید؛ اگر توکن افشا شد، از BotFather آن را تعویض کنید.
- یک سرویس polling از این ربات اجرا کنید؛ چند replica هم‌زمان می‌تواند باعث تداخل دریافت updateها شود.
- SQLite برای نسخه کوچک و یک نمونه مناسب است. برای مقیاس بزرگ، PostgreSQL و migration را در نظر بگیرید.
- قبل از فروش واقعی، بکاپ، محدودسازی نرخ، ثبت رویدادهای مدیریتی و سیاست پشتیبانی/بازپرداخت اضافه کنید.
